## Implemented

- Preserve original-language captions and transcribe available audio. Translate into `settings/cooking.voiceLanguage`, also used for recipe text.
- Reuse source metadata; retrieve video and audio independently; inspect duration with ffprobe when metadata omits it. Download progressive media in validated byte ranges; use the existing yt-dlp dependency for HLS through the public-IP-only proxy.
- Sample up to 24 frames, denser for short clips. Fall back to up to six public post images without falsely labeling them video frames. Try embedded video on websites when written instructions are insufficient.
- Search the exact URL/post ID and creator rather than substituting a similar recipe. Keep third-party transcriptions attributed as supplemental evidence.
- Verify the draft against the evidence, including displayed quantities, water, ingredient additions, step order, timing and pressure release.
- Optionally send public YouTube URLs to Vertex AI's native video reader when transcript or frames are missing. Preserve timestamped original speech and separate visual observations in the import record. Never use cookies or bypass login walls.

The native reader uses existing Firebase application-default credentials and REST calls, not another SDK. `YOUTUBE_VIDEO_MODEL=gemini-2.5-flash` enables it; absence disables it. Its video input is capped at 20 minutes. Model usage is recorded in `aiRuns` under provider `google`, task `source_video`. The source remains untrusted data, not instructions. Long, inaccessible or insufficient sources can still fail; this is not a guarantee that every social link is publicly readable.

### Pipeline completeness

The user clarified that preventing omissions in the parsing pipeline is the priority. The first revision (`companion-10`) produced its timing checklist and corrected recipe in the same response, allowing the same omission to appear in both. `companion-11` introduced an independent source record. A later captured live failure showed that the source record itself could omit a required wait and the second pass could copy that omission. `companion-12` added source-passage reviews, but live checks found that grouped reviews could hide cooking evidence in a broad context category. The current revision, `companion-13`, reuses the two existing model calls and requires individual review obligations derived from the original evidence by code:

1. Read the complete available evidence into a source record of ingredients, ordered actions, explicit durations, supporting source details, alternatives and uncertainties. This pass receives no draft recipe and does not scale or adapt quantities. Instructions retain technique, movements, repetitions and visual endpoints; immediate wait setup such as covering a bowl belongs with that wait.
2. Build the app recipe against the original evidence and that fixed source record. Each recorded action must have its own step with the same ID and order. Explicit durations must match; an unknown duration cannot become an unmarked estimate. Ingredient IDs must be preserved. Alternatives and warnings are carried forward automatically. Independently review every supplied source passage exactly once, in order, with its own decision. Cooking instructions must map to recipe steps, ingredient-only passages to ingredients, and exclusions need a stated reason. A source passage containing both a default route and an alternative must retain the complete default route, including its waits. An identified omission makes the import insufficient or fails validation instead of saving it.

Coverage validation runs after normalization and again before saving. A missing or merged recorded action, an omitted recorded untimed safety action, a shifted duration, or an added/removed ingredient fails the import. A second-pass response cannot replace the original source record with a shorter checklist. Missing, duplicate or unknown passage IDs, invalid step references, and review findings marked missing also prevent saving. The source record, expected passage IDs and model-run ID are retained before normalization; the returned review is retained even if validation fails. Timing failures report the source duration, returned duration and estimate flag.

Shared-cache version changes to `companion-13`. A cache hit must pass both source-record and passage-review validation; missing or inconsistent records trigger fresh parsing. A successful parse replaces an invalid cache entry. Failed parses never populate the cookbook or shared cache.

Source packaging also no longer slices serialized JSON at 115,000 characters, which could cut off later evidence and produce malformed JSON. Original/translated speech and video observations stay in their own complete block. Inputs above the explicit 500,000-character text limit are rejected rather than silently shortened at this boundary. Upstream source-reader limits still apply.

Passages are generated from written text, structured/linked recipes, original and translated speech, video observations and source-image references. Text is divided at line and sentence boundaries without interpreting duration words or relying on one language. At most 2,000 passages are accepted; larger sources fail explicitly. Grouped decisions are rejected. The second pass's output limit is 24,000 tokens and its timeout is four minutes to accommodate individual reviews. No dependency or model call was added, but reviewing the additional passages consumes more tokens.

These checks protect recorded facts and make skipped source evidence detectable. Source interpretation remains model-dependent: a reviewer can still incorrectly label an instruction as context or incorrectly claim a step covers it. The regression tests establish enforcement of the review contract, not that an AI reviewer will always identify every omission. Live validation demonstrated the individual-review format and the focaccia timing sequence, but manual review still found omitted ingredient-strength and dough-stopping details. The final prompt/schema descriptions explicitly preserve ingredient suitability requirements and visual/tactile stopping conditions as recipe facts; this last clarification has passed the offline suite but has not had another live provider check.
